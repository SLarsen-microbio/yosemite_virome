# Auxiliary Metabolic Gene Analysis

This directory contains the workflow used to identify and summarize auxiliary
metabolic genes (AMGs) in the corrected 532-vOTU Yosemite viral catalog and to
quantify the contribution of AMG-carrying vOTUs to the viral community.

## Workflow

### 1. VIBRANT annotation

`01_run_vibrant.sh`

AMGs were annotated with VIBRANT v1.2.1 using the 532-vOTU representative
catalog as input. VIBRANT was run in virome mode with 8 threads.

The native `VIBRANT_AMG_individuals` table provides the individual AMG
annotations used for downstream analyses.

### 2. AMG summaries

`02_summarize_amgs.py`

This script summarizes the VIBRANT AMG annotations to produce:

- AMG instance counts by KEGG Orthology (KO)
- AMG instance and unique-KO counts per vOTU
- AMG instance counts by broad metabolic category

Some KOs occur in more than one broad KEGG metabolic category. To make the
category summary reproducible, the analysis uses the explicit KO-to-primary-
category mapping in:

`../../metadata/amg/votu532_AMG_KO_primary_category.tsv`

This mapping records the primary category used in the final analysis rather
than assigning categories programmatically when a KO occurs in multiple
categories.

### 3. AMG abundance within viral communities

`03_calculate_amg_abundance_fraction.py`

This script integrates the VIBRANT AMG annotations with the breadth-filtered
532-vOTU RPKM matrix produced by the read-recruitment workflow.

For each sample it calculates:

- total viral RPKM
- RPKM attributable to AMG-carrying vOTUs
- RPKM attributable to non-AMG vOTUs
- percentage of total viral RPKM attributable to AMG-carrying vOTUs
- number of detected AMG-carrying vOTUs
- total number of detected vOTUs

VIBRANT can report AMG annotations on fragments generated from an input
scaffold. Fragment identifiers ending in `_fragment_N` are therefore
normalized back to the corresponding parent vOTU identifier before matching
AMG-carrying vOTUs to the RPKM matrix.

A vOTU is considered detected in this analysis when its breadth-filtered RPKM
is greater than zero. The breadth filtering itself is performed upstream in
the read-recruitment workflow using the 75% genome-breadth threshold.

## Relationship to upstream analyses

This workflow depends on:

1. the corrected 532-vOTU representative catalog generated by
   `../04_votu_clustering/`
2. the breadth-filtered 532-vOTU RPKM matrix generated by
   `../05_read_recruitment/`

VIBRANT annotations are therefore performed on the same vOTU catalog used for
community-level read recruitment.
